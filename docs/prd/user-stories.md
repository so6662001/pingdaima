# 用户故事与验收标准

> 配套主文档：[PRD.md](../PRD.md)。按 Epic 组织，每条故事包含角色-需要-价值三段式描述、验收标准（Given / When / Then）、优先级与关联的功能需求编号。
>
> 优先级采用 MoSCoW：**Must**（本期必须）/ **Should**（本期应该）/ **Could**（有余力则做）。

## 故事编号规范

`US-<模块码>-<序号>`，模块码：TK 工单、CU 客户、RQ 需求、PD 产品、PJ 项目、AG 敏捷、BD 看板、TS 测试、DV 代码、WL 工时、PE 人效、MT 度量、RT 复盘、NT 推送、PO 门户、ST 设置。

## Epic 1 工单受理与分诊

**目标**：把散落在电话、企业微信、邮件、开放平台的客户声音，收敛成结构化、有 SLA、可转化的工单。

### US-TK-01 多渠道工单受理

> 作为**客服一线**，我需要在一个列表里管理所有渠道进来的工单并关联到客户，以便不再在多个系统之间切换、不漏单。

**验收标准**

- Given 我在工单列表页，When 我按渠道、状态、优先级、客户等级任意组合筛选，Then 列表实时更新且筛选条件可保存为常用视图。
- Given 一条工单来自"客户经理"渠道，When 我打开工单，Then 能看到客户名称、等级、行业与该客户历史工单数，并可一键跳转客户 360。
- Given 我在创建工单，When 我选择工单类型，Then 表单自动带出该类型的专属字段、默认优先级与默认处理组。
- Given 工单标题与已有工单高度相似，When 我提交，Then 系统提示"疑似重复"并展示相似工单列表，我可以选择合并或继续创建。

**优先级**：Must　**关联**：FR-TK-01

### US-TK-02 自定义工单类型

> 作为**服务主管**，我需要自定义工单类型及其专属字段、SLA、处理组与可转换目标，以便不同业务场景用不同的收集口径。

**验收标准**

- Given 我在工单类型配置页，When 我新建"数据订正"类型并定义"订正范围/数据依据/授权人/影响金额"四个必填字段，Then 该类型的工单创建表单立即生效，无需发版。
- Given 某类型配置了默认 SLA（P2 · 2 小时响应 / 1 天解决），When 用该类型创建工单，Then SLA 时钟按此配置启动。
- Given 某类型配置了可转换目标为"缺陷 · 项目"，When 我在分诊时尝试转为需求，Then 系统提示该类型不允许转需求。
- Given 我停用某个类型，When 已有该类型的历史工单，Then 历史工单正常显示，但新建时不再出现该类型。

**优先级**：Must　**关联**：FR-TK-02

### US-TK-03 SLA 时钟与升级

> 作为**服务主管**，我需要工单 SLA 自动计时、预警与超时升级，以便对客户承诺可控而不是靠人盯。

**验收标准**

- Given 工单创建，When 尚未首次响应，Then 响应时钟运行中并在列表显示剩余时间；首次响应后响应时钟停止。
- Given 工单状态变为"待客户确认"，When 客户尚未回复，Then 解决时钟暂停，客户回复后自动恢复。
- Given SLA 剩余 30%，When 达到该阈值，Then 系统推送处理人与服务主管。
- Given SLA 归零仍未解决，When 超时，Then 工单标红、自动升级至技术负责人、`escalation_level` 加一并写审计日志。

**优先级**：Must　**关联**：FR-TK-03

### US-TK-04 工单池分诊

> 作为**轮值分诊的产品经理**，我需要在工单池里批量判定工单性质，以便把客户声音高效转成结构化需求或缺陷。

**验收标准**

- Given 我打开工单池，When 页面加载，Then 系统已完成相似度聚类，并对每条工单给出预判结论、置信度与预判依据。
- Given 一组相似工单（相似度 ≥ 0.78），When 我点击"合并并提需求"，Then 合并为一条需求，客户影响面（呼声数与加权值）自动叠加，所有来源工单保留反查链接。
- Given 我判定某工单为"不予处理"，When 提交，Then 必须填写理由，且系统生成对客回复草稿。
- Given 我批量选中 10 条咨询类工单，When 点击"转 FAQ"，Then 批量生成知识库草稿并关闭工单。

**优先级**：Must　**关联**：FR-TK-04

### US-TK-05 工单转需求与缺陷

> 作为**产品经理**，我需要把工单一键转成需求或缺陷并保留双向溯源，以便任何时候都能回答"这条需求是谁提的"。

**验收标准**

- Given 一条"需求建议"工单，When 我点击转需求，Then 需求自动继承标题、描述、客户、渠道与影响金额，且 `req_source` 记录来源单号。
- Given 需求已由多条工单合并而来，When 我在需求详情查看来源，Then 能看到全部来源工单及各自客户。
- Given 需求上线，When 状态流转到已发布，Then 系统自动通知客户经理与关联客户群，并在来源工单上追加"已交付"记录。
- Given 一条"故障报障"工单转为缺陷，When 缺陷修复并发布，Then 工单自动流转到"待验证"并通知处理人。

**优先级**：Must　**关联**：FR-TK-05

## Epic 2 需求池与优先级

**目标**：五类来源汇入同一个需求池，用公开的评分模型排序，用 DoR 卡住质量。

### US-RQ-01 统一需求池

> 作为**产品总监**，我需要所有来源的需求都汇入同一个池子并保留来源，以便不再出现同一诉求重复立项。

**验收标准**

- Given 需求来自工单/客户反馈/产品规划/监管合规/数据洞察，When 我在需求池查看，Then 每条需求都显示来源渠道标签与来源单号。
- Given 我按"客户呼声"排序，When 列表刷新，Then 按关联客户数与加权值降序排列。
- Given 我在需求池搜索，When 输入关键词，Then 同时匹配标题、描述、来源单号与客户名称。
- Given 存在两条高度相似的需求，When 系统检测到，Then 在需求池顶部提示疑似重复并支持一键合并。

**优先级**：Must　**关联**：FR-RQ-01

### US-RQ-02 需求富化

> 作为**产品经理**，我需要系统从来源工单自动补全需求的背景、收益与验收标准，以便减少重复劳动。

**验收标准**

- Given 一条由工单转来的需求缺少业务背景，When 我点击"智能富化"，Then 系统基于来源工单内容生成背景、预期收益、验收标准与客户影响面草稿。
- Given 富化结果生成，When 我查看，Then 每一段都标注来源依据，且我可以逐段采纳或修改后采纳。
- Given 我未采纳任何内容，When 我关闭富化面板，Then 需求内容保持不变。

**优先级**：Should　**关联**：FR-RQ-02

### US-RQ-03 重复识别与合并

> 作为**产品经理**，我需要识别并合并重复需求，以便客户影响面能正确累加。

**验收标准**

- Given 两条需求相似度 ≥ 0.78，When 我执行合并，Then 保留主需求，被合并需求转为"已合并"并指向主需求。
- Given 合并完成，When 我查看主需求，Then 客户呼声数、加权呼声、来源工单全部叠加，优先级得分自动重算。
- Given 合并是误操作，When 我在 7 天内点击"撤销合并"，Then 恢复为两条独立需求及各自的关联。

**优先级**：Should　**关联**：FR-RQ-03

### US-RQ-04 DoR 就绪度检查

> 作为**产品总监**，我需要用就绪度检查卡住不合格需求，以便减少进入迭代后的返工。

**验收标准**

- Given 一条需求的 DoR 检查项未全部达标，When 我尝试提交评审，Then 系统阻止并列出未达标项（业务背景、收益可量化、AC ≥ 3 条且可测试、已关联来源、已评分、方案已评审、已拆分为 ≤ 8 故事点）。
- Given 我在清洗页查看 DoR 达标率，When 页面加载，Then 展示每项的整体达标率并高亮最低项。
- Given 某需求为紧急合规类，When 产品总监选择"豁免 DoR"，Then 允许进入评审但记录豁免原因与审批人。

**优先级**：Must　**关联**：FR-RQ-04

### US-RQ-05 可配置优先级模型

> 作为**产品总监**，我需要优先级算法可配置、可解释、可版本化，以便排期结论能向业务方讲清楚。

**验收标准**

- Given 我在优先级模型页，When 我切换算法（加权价值÷工作量 / RICE / WSJF / 纯加权 / 自定义表达式），Then 因素表、公式说明与需求排序结果同步变化。
- Given 我调整某个因素权重，When 保存，Then 实时预览排序变化，并提示"将生成新的模型版本 Vn"。
- Given 模型升级为新版本，When 我查看历史需求，Then 其得分仍显示计算时所用的模型版本与因素快照。
- Given 一条需求命中合规强制规则，When 计算得分，Then 直接置顶并在得分旁标注"合规强制"。
- Given 我点击任一需求的得分，When 展开，Then 显示各因素得分、权重与最终计算过程。

**优先级**：Must　**关联**：FR-RQ-05

### US-RQ-06 需求评审流程

> 作为**产品总监**，我需要标准化的多节点评审流程并留痕，以便决策过程可追溯。

**验收标准**

- Given 需求进入评审，When 我查看评审流程条，Then 显示 7 个节点及各自状态、评审人、SLA 与待处理数量。
- Given 我点击某个评审节点，When 展开，Then 显示该节点的准入准出条件与当前待处理需求清单。
- Given 价值评审会进行中，When 逐条投票，Then 记录每位评审人的投票与意见，形成可导出的会议纪要。
- Given 某评审节点超过 SLA，When 超时，Then 推送评审人与其主管，并在需求上标记"评审超时"。

**优先级**：Must　**关联**：FR-RQ-06

### US-RQ-07 需求阶段计划

> 作为**项目经理**，我需要知道每条需求预计什么时候开始设计、开始编码、提测、完成，以便提前协调资源与测试排期。

**验收标准**

- Given 需求已排期，When 我查看需求详情，Then 显示设计/编码/联调/测试/发布五个阶段的计划起止、实际起止、负责人与进度。
- Given 某阶段实际开始晚于计划 ≥ 1 天，When 系统检测到，Then 该阶段标红并推送负责人、项目经理与产品总监。
- Given 需求工作量重新评估，When 我点击"智能重排"，Then 系统按新工作量重算后续阶段计划并标注变化量。
- Given 我在需求列表切换到"阶段排期"视图，When 按负责人或版本分组，Then 甘特图按分组重排并显示分组汇总行。

**优先级**：Must　**关联**：FR-RQ-07

### US-RQ-08 需求拆解

> 作为**研发负责人**，我需要把需求灵活拆成用户故事与任务，以便按团队习惯组织交付。

**验收标准**

- Given 我在需求拆解工作台，When 我选择拆解模板（如"前后端分离标准拆解"），Then 自动生成对应的故事与任务骨架。
- Given 我拆出的子项，When 保存，Then 子项自动继承需求的阶段计划、目标版本与客户关联。
- Given 需求已拆解，When 我查看需求进度，Then 进度按子项加权自动聚合，而不是手工填写。
- Given 某个故事超过 8 点，When 我保存，Then 系统提示"建议继续拆分"（提示而非阻断）。

**优先级**：Must　**关联**：FR-RQ-08

### US-RQ-09 需求推送到项目

> 作为**产品经理**，我需要把需求一键推送到项目管理，以便交付团队立即可以开工。

**验收标准**

- Given 需求已完成拆解与排期，When 我点击"推送到项目管理"，Then 选择目标项目与迭代，并可选择"直接指派"或"投放任务池"。
- Given 推送完成，When 我回到需求详情，Then 子工作项已关联并显示各自状态。
- Given 目标迭代容量不足，When 我推送，Then 系统告警并显示超出的点数，可选择强制推送（记录范围变更）。

**优先级**：Must　**关联**：FR-RQ-09

### US-RQ-10 需求归档与复活

> 作为**产品总监**，我需要暂缓与不做的需求进归档库而不是被删除，以便未来能检索与复活。

**验收标准**

- Given 需求被驳回或长期无进展，When 我归档，Then 必须选择归档原因（重复、不符定位、价值不足、技术不可行、已由其他方案覆盖）。
- Given 需求已归档，When 我在归档库搜索，Then 能按原因、时间、来源客户检索到。
- Given 归档需求需要重启，When 我点击"复活"，Then 回到"待评审"，保留全部历史关联，并按当前模型重新评分。

**优先级**：Should　**关联**：FR-RQ-10

## Epic 3 产品与路线图

### US-PD-01 产品全景

> 作为**产品负责人**，我需要一个产品维度的全景视图，以便掌握这条产品线的健康度与规划。

**验收标准**

- Given 我点击产品卡片，When 进入产品详情，Then 看到概览、能力与模块、需求与路线图、版本与发布、客户与反馈、产品指标、产品配置七个页签。
- Given 产品配置了北极星指标，When 我查看概览，Then 显示该指标的当前值与趋势。
- Given 我在产品配置页修改产品负责人与可见范围，When 保存，Then 立即生效并写审计日志。

**优先级**：Must　**关联**：FR-PD-01

### US-PD-02 多视角路线图

> 作为**产品经理**，我需要路线图能按时间轴、版本、迭代、里程碑与 Now-Next-Later 五种视角展示，以便面向不同听众讲同一份规划。

**验收标准**

- Given 我在路线图页，When 切换视角，Then 同一批特性按新视角重新组织展示，数据不变。
- Given 某特性跨多个迭代，When 在迭代视角查看，Then 正确显示跨度而不是重复出现。
- Given 我调整某特性的计划时间，When 保存，Then 所有视角同步更新。

**优先级**：Must　**关联**：FR-PD-02

### US-PD-03 路线图关联客户反馈

> 作为**产品经理**，我需要在路线图上直接看到每个特性背后的客户，以便和客户经理沟通时有据可依。

**验收标准**

- Given 某路线图条目关联了客户诉求，When 我查看，Then 显示客户数徽标，点击展开客户列表与原始反馈摘要。
- Given 某特性无任何客户诉求支撑，When 我查看，Then 显示"内部驱动"标识，便于评估投入合理性。

**优先级**：Should　**关联**：FR-PD-03

### US-PD-04 路线图对外同步

> 作为**产品总监**，我需要选择性地把路线图公开给客户与业务团队，以便减少重复解释。

**验收标准**

- Given 某条目标记为"对外可见"，When 业务方访问门户，Then 能看到该条目的名称、所属阶段（Now/Next/Later）与预计时间区间，但看不到内部工时与人员信息。
- Given 某条目未标记对外可见，When 业务方访问门户，Then 完全不可见（不显示占位）。
- Given 对外条目的计划发生变更，When 变更保存，Then 门户同步更新并给订阅者推送变更提醒。

**优先级**：Should　**关联**：FR-PD-04

## Epic 4 项目与迭代

### US-PJ-01 项目组合视图

> 作为**研发中心总裁**，我需要一眼看到所有项目的健康度、进度与预算消耗，以便及早发现风险项目。

**验收标准**

- Given 我打开项目管理，When 页面加载，Then 显示项目列表（产品线、项目经理、团队、当前迭代、进度、需求/缺陷数、预算消耗、健康度、周期）与项目组合甘特。
- Given 某项目健康度为"风险"，When 我查看，Then 高亮显示并给出风险原因（进度偏离、阻塞数、预算超支）。

**优先级**：Must　**关联**：FR-PJ-01

### US-PJ-02 多版本迭代规划

> 作为**Scrum Master**，我需要同时规划 Backlog 与多个 Sprint，以便提前安排两三个迭代的优先级而不是只顾眼前。

**验收标准**

- Given 我打开迭代规划板，When 页面加载，Then 并排显示 Backlog 与多个 Sprint 列，每列显示承诺点数、容量与目标。
- Given 我把一张卡片从 Backlog 拖入 Sprint，When 拖放完成，Then 该 Sprint 的承诺点数实时更新；超出容量时列头变红并提示超出量。
- Given 迭代已开始，When 我再拖入新卡片，Then 系统提示"这将造成范围变更"，确认后记录到范围变更清单。
- Given 我为某个 Sprint 设置迭代目标，When 保存，Then 目标显示在看板顶部与站会页面。

**优先级**：Must　**关联**：FR-PJ-02

### US-PJ-03 资源排期与容量

> 作为**项目经理**，我需要按人按周排期并看到真实可用容量，以便知道团队是否已经排满。

**验收标准**

- Given 我打开资源排期表，When 页面加载，Then 显示成员 × 周的热力矩阵，单元格显示分配到的项目与占比。
- Given 某成员本周请假两天，When 计算容量，Then 可用容量按 `基线 − 请假 − 会议 − 值班 − 缓冲` 自动扣减。
- Given 某成员在同一周被两个项目合计排到 120%，When 保存，Then 单元格标红并在冲突清单中列出。
- Given 我点击某个单元格，When 打开快速排期弹窗，Then 可调整分配比例并即时看到冲突是否解除。

**优先级**：Must　**关联**：FR-PJ-03

### US-PJ-04 任务池自助认领

> 作为**研发工程师**，我需要自己从任务池里领任务，以便按自己的节奏与专长安排工作。

**验收标准**

- Given 我提交反馈时勾选匿名，When 反馈展示，Then 不显示提交人（管理员也不可见）。
- Given 投票阶段，When 我投票，Then 每人最多 5 票，投票结束后按票数排序进入讨论。

**优先级**：Should　**关联**：FR-RT-02

### US-RT-03 行动项闭环

> 作为**研发负责人**，我需要复盘产出的改进项能真正落地，以便复盘不流于形式。

**验收标准**

- Given 我创建行动项，When 提交，Then 必须通过 SMART 校验（具体、可衡量、单一责任人、相关、有截止日期），否则不允许保存。
- Given 行动项已立项，When 保存，Then 自动生成任务工作项并进入下一迭代。
- Given 截止前 2 天未完成，When 到达时间点，Then 推送责任人与主持人；连续两次延期升级至研发管理委员会。
- Given 我开始新一次复盘，When 打开复盘页，Then 首先展示上次复盘行动项的闭环率与未闭环清单。

**优先级**：Must　**关联**：FR-RT-03

## Epic 11 消息与对外可见

### US-NT-01 企业微信集成

> 作为**研发工程师**，我需要在企业微信里收到与我相关的研发通知，以便不用一直盯着平台。

**验收标准**

- Given 我的企业微信账号已绑定，When 有与我相关的事件，Then 我在企业微信收到卡片消息，包含关键信息与操作按钮（去处理/认领/我知道了）。
- Given 我点击卡片上的"认领"，When 操作成功，Then 平台内任务状态同步更新，无需打开网页。

**优先级**：Must　**关联**：FR-NT-01

### US-NT-02 推送规则配置

> 作为**平台管理员**，我需要配置推送规则的触发条件、接收对象、渠道与时机，以便消息既不缺失也不打扰。

**验收标准**

- Given 我在推送规则页，When 我编辑某条规则，Then 可配置 WHEN（触发条件）、WHO（接收对象）、渠道（应用消息/群机器人）与时机（实时/定时/周期）。
- Given 某规则被停用，When 对应事件发生，Then 不再推送，但事件仍记录在工作项时间线。
- Given 某规则本月打开率长期低于阈值，When 我查看推送效果，Then 系统提示该规则可能是噪音，建议调整或停用。

**优先级**：Must　**关联**：FR-NT-02

### US-NT-03 订阅与免打扰

> 作为**平台用户**，我需要自主设置订阅与免打扰时段，以便不被非紧急消息打扰。

**验收标准**

- Given 我关闭某个分类的订阅，When 该类事件发生，Then 不再推送给我。
- Given 我设置了免打扰时段，When 在该时段内产生普通消息，Then 延后到时段结束再推送。
- Given 在免打扰时段内产生 P0 或合规类消息，When 消息生成，Then 立即穿透免打扰推送。

**优先级**：Should　**关联**：FR-NT-03

### US-PO-01 业务方进度门户

> 作为**业务方 / 客户经理**，我需要一个不需要懂研发术语就能看懂的进度页面，以便随时回答客户"做到哪了"。

**验收标准**

- Given 我访问门户，When 页面加载，Then 看到我关心的需求、工单与版本迭代的进度，用业务语言描述（如"开发中，预计 9 月 30 日上线"）而非内部状态码。
- Given 某需求内部状态变更，When 变更发生，Then 门户进度同步更新，无需人工同步。
- Given 我不具备内部权限，When 我访问门户，Then 看不到工时、人员、内部评论等信息。

**优先级**：Must　**关联**：FR-PO-01

### US-PO-02 对外路线图

> 作为**客户经理**，我需要向客户展示 Now/Next/Later 路线图并标出客户提交的特性，以便增强客户信心。

**验收标准**

- Given 某特性由客户诉求驱动，When 在门户展示，Then 标注"来自用户反馈"。
- Given 我订阅了某条需求，When 其阶段或计划变更，Then 我收到变更通知。

**优先级**：Should　**关联**：FR-PO-02

## Epic 12 系统配置

### US-ST-01 工作项类型与颗粒度

> 作为**平台管理员**，我需要自定义工作项类型及其层级、允许的子类型与专属属性，以便匹配不同团队的管理颗粒度。

**验收标准**

- Given 我在工作项类型配置页，When 我查看，Then 显示 7 类内置类型（Epic / 需求 / 用户故事 / 任务 / 缺陷 / 技术债 / 测试用例）及其层级、允许子类型、专属属性、状态数、估算单位、是否可自助认领。
- Given 我新建一个自定义类型，When 保存，Then 立即可在创建工作项时选择，无需发版。
- Given 某类型被设为不允许自助认领，When 该类型工作项进入任务池，Then 不显示"认领"按钮。

**优先级**：Must　**关联**：FR-ST-01

### US-ST-02 状态机可视化配置

> 作为**平台管理员**，我需要按工作项类型配置状态机，以便不同类型有各自合理的流转路径。

**验收标准**

- Given 我在工作流配置页切换工作项类型，When 切换完成，Then 状态机图重绘为该类型的状态与流转（实线主流程、虚线异常流转）。
- Given 我新增一个状态，When 保存，Then 需要指定归类（初始/进行/等待/终态）、可操作角色与停留超时阈值。
- Given 我删除一个仍有工作项停留的状态，When 保存，Then 被阻止并提示需先迁移这些工作项。

**优先级**：Must　**关联**：FR-ST-02

### US-ST-03 自定义字段与自动化

> 作为**平台管理员**，我需要自定义字段与自动化规则，以便流程随组织演进而不必改代码。

**验收标准**

- Given 我新增一个自定义字段，When 配置适用对象、类型、是否必填、是否用于度量，Then 立即在对应表单生效。
- Given 我配置一条自动化规则（当 X 发生则 Y），When 触发条件满足，Then 自动执行并在工作项时间线记录"由自动化规则触发"。

**优先级**：Should　**关联**：FR-ST-03

### US-ST-04 安全与审计

> 作为**安全负责人**，我需要敏感操作全部留痕并支持脱敏与导出审批，以便满足合规要求。

**验收标准**

- Given 发生权限变更、数据导出、门禁豁免、强制流转，When 操作完成，Then 写入审计日志（操作人、对象、变更前后、IP、时间），保留 ≥ 3 年。
- Given 我的角色不允许查看商户信息，When 我打开相关页面，Then 敏感字段按规则脱敏显示。
- Given 我申请导出数据，When 提交，Then 需二次审批，审批通过后导出并记录导出范围。

**优先级**：Must　**关联**：FR-ST-04
